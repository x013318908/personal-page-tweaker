CHROME WEB STORE REVIEW

Permission Justifications

Updated November 10, 2026 · Version 1.1.0

Single purpose

Personal Page Tweaker lets users customize the appearance and behavior of permitted websites using their own per-site CSS and JavaScript rules.

Required permissions

activeTab

Read the active tab's URL after the user opens the extension popup, show the current site, and create a customization rule for that site. It does not grant persistent access to all websites.

scripting

Register and run bundled CSS helper content scripts on sites for which the user has granted optional host access. These helpers apply or remove saved CSS on open pages and update matching when a page URL changes. User-provided JavaScript is executed separately through chrome.userScripts.

storage

Store user-created rule names, match/exclusion patterns, CSS, JavaScript, enabled states, execution options and timestamps in chrome.storage.local. One local recovery copy is kept before a full JSON import. Storage is restricted to trusted extension contexts.

userScripts

Register JavaScript explicitly entered or imported by the user for sites matching their rules and granted host access. Each non-empty timing editor runs at document_start, document_end or document_idle. The default world is USER_SCRIPT; users may select MAIN. User-script messaging to extension APIs is not enabled. Chrome's Allow User Scripts toggle is required.

Optional site access

http://*/* and https://*/*

The extension supports user-selected HTTP and HTTPS sites, so these patterns are declared as optional_host_permissions. By default, access is requested for the host patterns in the user's rule when they save/enable it or click the site-permission button. Users may explicitly enable an all-site access option in settings, which requests both patterns together through Chrome's permission prompt. The option is off by default, and cancelling leaves individual-site requests available. It avoids repeated site prompts for users managing rules across many websites. Declaring these optional patterns does not itself grant access. Runtime matching always applies the user's rule patterns, exclusions and frame choice; broad permission does not automatically run code on unconfigured pages.

Turning all-site access off removes HTTP/HTTPS host grants, including earlier individual grants, under Chrome's permission semantics. The settings explain this and retain the individual-site permission button. Chrome manages actual grants; the UI reflects browser-side changes, and JSON import never grants access.

A user may also intentionally enter a wildcard rule covering many sites. It remains an explicit permission request for that user-selected scope. There are no required host_permissions.

User-provided code

Personal Page Tweaker is a user-script manager. Users explicitly enter JavaScript in the editor or select a local .user.js/backup file. Only this user-provided code is executed through chrome.userScripts on sites matching the user's rules and granted host access. Access is granted per site by default; users can explicitly opt into all HTTP/HTTPS sites. The extension does not fetch executable code from URLs, CDNs or developer servers, use eval/new Function in extension contexts, or automatically install/update scripts. All extension logic is in the submitted package. User-script messaging to extension APIs is not enabled.

Extension pages use a bundled-only script CSP. User code is not evaluated in an extension page or passed to scripting.executeScript. See the User Scripts API and Manifest V3 policy for the applicable API.

Data use summary

Page URLs are matched locally. Permitted page content is customized as requested. Rules, code and URL conditions stay in local extension storage, or in a local backup file explicitly exported by the user. The developer receives no data. User scripts can make their own network requests as written; this is disclosed in the settings and privacy policy.

No downloads, history, cookies, tabs, debugger, notifications, geolocation, camera or microphone permission is requested. JSON export uses a standard local file download.

権限について（日本語）

目的は、ユーザーが選んだサイトを自分のCSSとJavaScriptでカスタマイズすることです。

  • activeTab: ポップアップを開いたときのURLから、現在のサイトを表示・設定作成します。
  • scripting: パッケージ内のCSS用処理を許可済みサイトで動かし、保存や停止を開いているページにも反映します。
  • storage: 設定とImport前の復旧用コピーを端末内に保存します。
  • userScripts: ユーザー自身が入力・取り込みしたJavaScriptを指定タイミングで実行します。
  • HTTP/HTTPSのホスト権限は、初期状態では対象サイトごとに許可を求めます。任意で設定画面から全サイトを一括許可でき、Chromeの確認をキャンセルしても個別許可で利用できます。いずれも各設定の対象URL・除外URL・フレーム条件に従って適用します。

一括許可を解除すると以前の個別許可も解除されます。必要なサイトは各設定の「権限を許可」で許可し直せます。実際の権限はChromeが管理し、Export/Importには含めません。

登録コードはページの情報を読んだり通信したりできます。拡張本体の管理処理は配布パッケージ内にあり、スクリプトURLからの自動取得・更新はしません。詳しくはプライバシーポリシーをご覧ください。
